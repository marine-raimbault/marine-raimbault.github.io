This post answers:

  • What happens to my app’s data when I open a second tab or reload the page?
  • Does a Vue store live once per tab, or once per browser?
  • When does Vue run a component’s created(), and what must already exist at that moment?
  • Why does a test crash before it sends a single request?

The model in three lines

Insight first, for a reader who builds web apps but never pictured the browser side: each tab is its own page with its own JavaScript memory; a reload or a new page throws that memory away; Vue runs created() once per component, right after the page’s JavaScript starts the app. Explain “JavaScript memory” and “store” (one shared object that holds the app’s data while the page is open) in plain words.

🖼 Drawing 1: two browser tabs side by side, each with its own box “memory: store, components”. An arrow “reload” from tab 1 to an empty box.

One store per tab: the browser’s processes

Answers “one store per tab?”. A process = a program with its own memory, walled off by the operating system; it gets turns on the CPU but doesn’t own one. Chrome runs several kinds: one browser process (address bar, tabs), one GPU process, networking shared by every tab (DNS cache, open connections: inside the browser process in the article’s picture, its own Network Service process in today’s desktop Chrome), and a renderer process per site that parses, renders and runs the page’s JavaScript. The Vue store lives in a renderer’s page memory, so: one per tab, gone on reload. Cookies and localStorage live on disk, per site, so every tab sees them. Source and images: Mariko Kosaka, Inside look at modern web browser, part 1.

🖼 Drawing 2a: Chrome as a building: one shared “network” room with a DNS phone book and a few open phone lines; two tab rooms (renderers), each with its own whiteboard “Vuex store”; a disk cupboard in the hall labelled “cookies, localStorage”, reachable from both rooms.

The crash: a test without the plugs

A browser test that mounts the grid with no store: created() throws TypeError: Cannot read properties of undefined (reading 'dispatch') on the first line, so the request never goes out. A network mock (explain MSW in one sentence) waits for a request that never comes. The lesson for a reader: separate “talks to the network” from “talks to something in memory”.

  1. Blind spot: yes, and it’s a common one. The simple model:
  • Each tab is its own page, with its own JavaScript memory.
  • A reload or a new page clears that memory, and the store with it.
  • Vue runs created() once for each component, right after the page’s JavaScript starts it up.

Read 📖 MDN: How browsers work (https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/How_browsers_work) (the parse → run → render steps), then the Vue lifecycle diagram (https://vuejs.org/guide/essentials/lifecycle.html). Use text, not a video: the diagram is the part that sticks.
